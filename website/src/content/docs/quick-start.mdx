You'll end up with Google's Rust style guide enforced by your formatter, linter and dependency checker, plus instructions your coding agent reads automatically. It takes about five minutes.

<Aside type="tip" title="Before you start">
You need Rust 1.95 or newer on the stable channel (`rustup update stable`) and an existing Cargo project. Nothing here changes your code; it only adds config files.
</Aside>

<Tabs syncKey="setup-path">
<TabItem label="Do it yourself" icon="seti:rust">

<Steps>

1. **Add the config files** (30 seconds)

   Run this from your project root. Files you already have are skipped, never overwritten.

   ```sh title="Terminal"
   base=https://daniakash.github.io/Google-Rust-Style-Guide/files
   for f in rustfmt.toml clippy.toml deny.toml rust-toolchain.toml AGENTS.md; do
     if [ -e "$f" ]; then echo "skipped $f (already exists)"; else curl -fsSLO "$base/$f"; fi
   done
   ```

   <FileTree>
   - your-project/
     - **AGENTS.md** instructions for coding agents
     - **clippy.toml** lint thresholds and banned APIs
     - **deny.toml** bans crates that run code before main()
     - **rust-toolchain.toml** pins the stable channel
     - **rustfmt.toml** the guide's formatting options
     - Cargo.toml
     - src/
   </FileTree>

2. **Turn on the lints** (1 minute)

   Pick your project shape. Your choice is remembered on every page.

   <Tabs syncKey="project-shape">
   <TabItem label="Single crate">

   **Single crate:** append the lint tables to your `Cargo.toml`.

   ```sh title="Terminal"
   curl -fsSL https://daniakash.github.io/Google-Rust-Style-Guide/files/crate-lints.toml >> Cargo.toml
   ```

   See exactly what gets added on the [Cargo.toml lints](/Google-Rust-Style-Guide/config/cargo-lints/) page.

   </TabItem>
   <TabItem label="Workspace">

   **Workspace:** append the lint tables to your workspace root `Cargo.toml`.

   ```sh title="Terminal"
   curl -fsSL https://daniakash.github.io/Google-Rust-Style-Guide/files/workspace-lints.toml >> Cargo.toml
   ```

   Then opt every member crate in by adding these two lines to its `Cargo.toml`:

   ```toml title="crates/<member>/Cargo.toml"
   [lints]
   workspace = true
   ```

   Or do all members at once:

   ```sh title="Terminal"
   # Run from the workspace root. Adjust crates/* to where your members live.
   for member in crates/*/Cargo.toml; do
     printf '\n[lints]\nworkspace = true\n' >> "$member"
   done
   ```

   See exactly what gets added on the [Cargo.toml lints](/Google-Rust-Style-Guide/config/cargo-lints/) page.

   </TabItem>
   </Tabs>

   <Aside type="caution">
   If your `Cargo.toml` already has a `[lints]` or `[workspace.lints]` table, Cargo will report a duplicate key. Merge the tables by hand instead of appending.
   </Aside>

3. **Point your coding agent at it** (10 seconds)

   Codex, Cursor, Gemini CLI, GitHub Copilot and most other agents read `AGENTS.md` automatically. Claude Code reads `CLAUDE.md`, so link it:

   ```sh title="Terminal"
   ln -s AGENTS.md CLAUDE.md
   ```

   If step 1 skipped `AGENTS.md` because you already have one, paste the [kit's AGENTS.md](/Google-Rust-Style-Guide/agents-md/) into it as a "Rust style" section.

4. **Verify** (2 minutes)

   Install nightly rustfmt (for three of the guide's formatting options) and cargo-deny once:

   ```sh title="Terminal (one time)"
   rustup toolchain install nightly --profile minimal --component rustfmt
   cargo install --locked cargo-deny
   ```

   Then run the three checks:

   ```sh title="Terminal"
   cargo +nightly fmt
   cargo clippy --workspace --all-targets -- -D warnings
   cargo deny check bans
   ```

   A brand-new `cargo new --lib` project shows three warnings. That's the kit working:

   ```text title="cargo clippy output"
   warning: this function could have a `#[must_use]` attribute
   warning: missing documentation for the crate
   warning: missing documentation for a function
   ```

   Fixing them takes three lines:

   ```diff lang="rust" title="src/lib.rs"
   +//! Adds numbers.
   +
   +/// Returns the sum of `left` and `right`.
   +#[must_use]
    pub fn add(left: u64, right: u64) -> u64 {
        left + right
    }
   ```

   When everything is green you'll see:

   ```text title="Terminal"
       Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.03s
   bans ok
   ```

</Steps>

</TabItem>

## Add it to CI

Make warnings block merges by running the same checks in CI with `-D warnings`:

```yaml title=".github/workflows/style.yml"
name: Style
on: [push, pull_request]

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: cargo clippy --workspace --all-targets -- -D warnings

  format:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: rustup toolchain install nightly --profile minimal --component rustfmt
      - run: cargo +nightly fmt --check

  deny:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: taiki-e/install-action@v2
        with:
          tool: cargo-deny
      - run: cargo deny check bans
```

## Troubleshooting

| You see | Why | Do this |
|---|---|---|
| ``Warning: can't set `hex_literal_case = Lower`, unstable features are only available in nightly channel.`` | Three of the guide's rustfmt options only exist on nightly rustfmt | Run `cargo +nightly fmt`. On stable the warning is harmless and the other options still apply. |
| ``unknown lint: `clippy::...` `` | Your toolchain is older than the kit's tested Rust 1.95 | `rustup update stable` |
| ``cannot override `workspace.lints` in `lints` `` | A member crate has both `[lints] workspace = true` and its own `[lints.*]` tables | Keep `workspace = true` and relax a lint at the crate root instead: `#![expect(clippy::lint_name, reason = "...")]` |
| `duplicate key` in `Cargo.toml` | Your `Cargo.toml` already had lint tables | Merge the appended tables into the existing ones by hand |
| ``error: no such command: `deny` `` | cargo-deny is a separate tool | `cargo install --locked cargo-deny` (or `brew install cargo-deny`) |
| ``use of a disallowed type `std::sync::Arc` `` | The guide asks you to justify shared ownership | Restructure to a single owner, or add `#[expect(clippy::disallowed_types, reason = "...")]` with the reason |
| Hundreds of warnings | Your codebase predates the kit | Follow the [phased rollout for existing codebases](/Google-Rust-Style-Guide/adopting/#existing-codebases) |

## Remove the kit

Changed your mind? Delete the five files and the lint tables:

```sh title="Terminal"
rm rustfmt.toml clippy.toml deny.toml rust-toolchain.toml AGENTS.md CLAUDE.md
```

Then remove everything from the `# Google Rust Style Guide lints` comment to the end of your `Cargo.toml`, and the `[lints] workspace = true` lines from member crates.
